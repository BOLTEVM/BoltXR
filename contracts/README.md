# Iced-Out XR Watches — mint contract

`src/IcedOutXRWatches.sol` — 150 ERC-721 watch wallets, minted in order (#1 first, the Mythic
#150 last), on a price curve that only rises:

| Mint | Price |
| --- | --- |
| #1 | 0.001 ETH |
| #25 | 0.003042 ETH |
| #50 | 0.009696 ETH |
| #75 | 0.0309 ETH |
| #100 | 0.09847 ETH |
| #125 | 0.3138 ETH |
| #149 | 0.9547 ETH |
| #150 | 1 ETH |

Every mint lifts the next price by about 4.75 % (`0.001 × 1000^((n−1)/149)`, 4 significant
figures). Selling out raises 22.05 ETH. The table lives in `src/WatchPriceTable.sol` and, for the
mint modal, `lib/mint/priceTable.ts` — both generated by `scripts/mint/build-price-table.mjs`;
`node scripts/mint/check-price-table.mjs` checks they agree.

## Phases

| Phase | Who can mint |
| --- | --- |
| `Closed` (0, at deploy) | nobody |
| `Allowlist` (1) | addresses holding at least `passMinBalance` of the pass token — an ERC-20, an ERC-721, or one id of an ERC-1155 |
| `Public` (2) | anyone |

The pass is checked live when minting. It decides who may mint during the allowlist phase; it is
not a one-claim-per-pass ticket (a pass can be lent or moved between wallets), so pair it with
`maxPerWallet`. If you need strictly one claim per pass, the contract needs a Merkle snapshot or
per-pass-id claims — say so and it can be added.

## Paying

`mint(quantity)` is payable. `msg.value` is the most the buyer agrees to pay: the contract charges
the price at execution and refunds the rest in the same transaction, and reverts with
`InsufficientPayment(required, sent)` if others minted first and the price moved past it. The mint
modal sends the current quote plus an optional "price protection" margin (the price as if two
more mints landed first) and shows the buyer both numbers.

Other guards: `ReentrancyGuard`, every token exists before any external call (receiver hooks,
the refund), `Ownable2Step` (ownership cannot be renounced — the proceeds would be stuck),
`maxPerWallet` (0 = none), `freezeMetadata()` (base URI locked; must be set first), ERC-2981
royalties (5 % by default) and ERC-4906 metadata refresh events.

## Build and test (Hardhat 3)

The watches ship on **Ethereum mainnet only**. There is no public testnet in the flow: everything
is tested on Hardhat's local chain first. Needs Node.js 22.13 or later.

```bash
cd contracts
pnpm add -D hardhat @nomicfoundation/hardhat-toolbox-viem @openzeppelin/contracts@^5 "github:foundry-rs/forge-std#v1.16.2"
pnpm test                # the Solidity tests in test/ (forge-std style; Hardhat runs them)
```

41 tests and a fuzz test: the curve, every phase and pass kind, refunds, stale quotes, the supply
and wallet limits, reentrancy from a receiver hook, refunds to contracts that refuse ETH, receivers
seeing a complete batch, metadata freezing, withdrawals, royalties and two-step ownership.
`remappings.txt` points `forge-std/` and `@openzeppelin/contracts/` at those npm packages.

> These sources were written and reviewed without a Solidity compiler at hand — run
> `pnpm test` before deploying anywhere, and have the contract reviewed before mainnet.

## The local chain: mint and wear without real ETH

```powershell
pnpm chain                                   # terminal 1: chain 31337 at http://127.0.0.1:8545
pnpm local                                   # terminal 2: deploy and open the public sale
$env:MINT_TO = "0xYourVaultAddress"; $env:MINT_COUNT = "2"; pnpm local   # …and mint two straight to your vault
```

(Commands are PowerShell; in bash write `MINT_TO=0x… MINT_COUNT=2 pnpm local`.)

`pnpm local` prints the two lines for the wallet's `.env.local`:

```bash
NEXT_PUBLIC_WATCH_CHAIN_ID=31337
NEXT_PUBLIC_WATCH_CONTRACT=0x5FbDB2315678afecb367f032d93F642f64180aa3   # a fresh node always gives this one
```

The wallet honours them on `pnpm dev` only; a built app always reads mainnet. Minting from the
mint modal with a browser wallet needs the network "Hardhat local" (http://127.0.0.1:8545,
chain 31337) and one of the test accounts `pnpm chain` prints, in a separate test profile: those
keys are public, never send real funds to them. The node forgets everything when it stops.

## Deploy to mainnet

```powershell
pnpm hardhat keystore set MAINNET_RPC_URL
pnpm hardhat keystore set MAINNET_PRIVATE_KEY           # the deployer: pays the gas
$env:WATCH_OWNER = "0xYourMultisig"                     # required — the owner
$env:WATCH_BASE_URI = "ar://<metadata manifest>/"       # token #7 → <base>007.json (or set it later)
$env:WATCH_PASS_TOKEN = "0xPassContract"                # optional now, settable later
$env:WATCH_PASS_KIND = "0"                              # 0 = ERC-20 / ERC-721, 1 = ERC-1155
$env:WATCH_MAX_PER_WALLET = "5"
pnpm deploy:mainnet                                     # prints the settings, sends nothing
$env:WATCH_CONFIRM = "mainnet"; pnpm deploy:mainnet     # deploys (real ETH)
```

Then put the address in **`lib/mint/config.ts`** (`CONTRACT_ADDRESS`) — or set
`NEXT_PUBLIC_WATCH_CONTRACT` at build time. The modal and the wallet's watch gating pick it up;
nothing else to change.

## Running the sale (owner)

A multisig owner calls these from its own app (for Safe: the transaction builder, with this
contract's ABI). An owner key held by Hardhat can use `scripts/owner.ts`:

```powershell
$env:WATCH = "0xTheContract"
$env:ACTION = "pass";           $env:ARG = "0xPassContract 0 0 1";   pnpm owner --network mainnet   # ERC-721 pass, need 1
$env:ACTION = "phase";          $env:ARG = "1";                      pnpm owner --network mainnet   # allowlist
$env:ACTION = "phase";          $env:ARG = "2";                      pnpm owner --network mainnet   # public
$env:ACTION = "max-per-wallet"; $env:ARG = "3";                      pnpm owner --network mainnet
$env:ACTION = "base-uri";       $env:ARG = "ar://<metadata manifest>/";                pnpm owner --network mainnet
$env:ACTION = "contract-uri";   $env:ARG = "ar://<metadata manifest>/collection.json"; pnpm owner --network mainnet
$env:ACTION = "freeze";         $env:ARG = "";                       pnpm owner --network mainnet
$env:ACTION = "withdraw";       $env:ARG = "0xTreasury";             pnpm owner --network mainnet
```

The same with `--network localhost` on the local chain.

## Metadata and art

The mint art, the token files and the 3D watches are not in this repository: they live in the
private watch module (checked out at `private/iced-out`, see the wallet README). Its
`scripts/mint/upload-arweave.mjs` puts the public part on Arweave — each token's studio stills,
the gallery thumbnails, the 150 token files and `collection.json` — and prints the `baseURI`
(`ar://<metadata manifest>/`) and `contractURI` (`…/collection.json`) to set above, and the
app's `NEXT_PUBLIC_WATCH_ART_BASE`. Arweave is public and permanent, so the 3D models never go
there; holders download theirs from the holder server, which checks `ownerOf` on mainnet first.
`freezeMetadata()` once the base URI is final.

Before uploading, read the descriptions: they describe a physical hardware wallet with diamonds
and an EAL6+ secure element. If buyers get a digital XR watch, the metadata should say that.
